# Instruções de trabalho

## Documentação e evidências

- Manter o README profissional e conciso, registrando o que foi feito, os resultados confirmados e as pendências. Instruções extensas ficam em `docs/`.
- A documentação visual faz parte do fechamento dos marcos importantes. Ao concluir uma configuração, integração, validação real ou funcionalidade com resultado visível, salvar a captura e atualizar o índice sem depender de novo pedido do usuário.
- Guardar capturas numeradas em `data/evidencias/`, com nomes descritivos. Atualizar `data/evidencias/INDICE.md` com data, origem, marco e o que a imagem efetivamente demonstra. A pasta `data/` é local e ignorada pelo Git.
- Revisar os prints enviados pelo usuário e incorporar os relevantes ao histórico. Preservar os arquivos originais e distinguir formulários de preparação de confirmações de conclusão.
- Capturar o estado real da interface. Resultados de terminal podem ser registrados como texto real quando não houver captura disponível; identificar o formato corretamente.
- Selecionar capturas sem senhas, tokens, chaves ou códigos de autenticação. Manter imagens com dados pessoais somente no arquivo local de evidências.
- Após cada marco, atualizar os registros em `docs/` e o resumo do README conforme o resultado observado. Testes locais, resposta de API e conferência visual são evidências distintas.

Preferência solicitada pelo usuário em 21/10/2026: manter documentação textual e visual continuamente durante o desenvolvimento.

Preferência complementada em 22/10/2026: Prints somente quando acrescentarem evidência visual útil; não produzir captura para cada microtarefa. Para validações de API e regras, usar resultados reais de testes/HTTP em texto ou JSON quando comprovarem melhor o resultado, mantendo o índice atualizado.
